## The bench scorecard verifies an install-identity signature on the baseline

`bench run --baseline` used to stop at "a signature is present" for any baseline not signed with the stub key, and reported neutral because nothing in the bench layer could check one. It now verifies the baseline's install-identity signature against a public key you supply with `--trusted-key FINGERPRINT=PATH` (the option `bench verify` already takes), and compares against the baseline when it verifies. A baseline whose signer has no trusted key, or whose signature does not verify, stays neutral with the reason in the summary. `evaluate_ci_scorecard` gains a `trusted_keys` argument and otherwise uses the keys of the verifier it is given, and `BenchVerifier` exposes them as a read-only `trusted_keys` property (#5902).
